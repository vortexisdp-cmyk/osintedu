BUG-001 🔴 Critical Layout & Overflow

Page-wide horizontal scroll on mobile — three root causes

What's wrong

Swiping left/right at 320–768px exposes 8–40px of phantom scroll. Root causes traced: (a) the hero's full-bleed decorative layer is sized with width:100vw + negative margin inside a padded container (100vw includes the scrollbar gutter); (b) prompt <pre> blocks use white-space:pre with no internal scrolling; (c) the video-formula chip row has flex-shrink:0 children with no overflow container. Do not bandage with overflow-x:hidden — fix the sources.

Location

.hero__decor (100vw layer) pre blocks — #basics, #text, #images, #music, #practices .formula-row — #video section
Fix · CSS
/* (a) full-bleed layer: never 100vw inside a padded parent */
.hero__decor {
  width: 100%;
  inset-inline: 0;          /* was: left:50%; margin-left:-50vw */
}

/* (b) every code / prompt block scrolls internally */
pre {
  max-width: 100%;
  overflow-x: auto;
  -webkit-overflow-scrolling: touch;
}

/* (c) chip rows become snap scrollers — last item fully visible */
.formula-row {
  display: flex;
  gap: 8px;
  overflow-x: auto;
  scroll-snap-type: x proximity;
  padding-inline: 4px;       /* stops first/last chip clipping */
  scroll-padding-inline: 4px;
}
.formula-row > * {
  flex: 0 0 auto;            /* keep shrink:0, now inside a scroller */
  scroll-snap-align: start;
}

/* guard rail ONLY — not the fix itself:
   html, body { overflow-x: clip; } */
BUG-002 🔴 Critical Layout & Overflow

Sticky header covers section headings after anchor jumps

What's wrong

Clicking any nav link (Основы, Текст, Изображения…) scrolls the target so its h2 lands underneath the ~64px sticky header. Users land mid-section with the title hidden and no visual anchor. scroll-margin-top is missing on every section[id].

Location

nav a[href^="#"] targets: #basics #text #images #music #video #practices #conclusion + header.site-header (sticky)
Fix · CSS
:root { --header-h: 64px; }   /* match the real header height */

section[id] {
  scroll-margin-top: calc(var(--header-h) + 16px);
}

html { scroll-behavior: smooth; }

@media (prefers-reduced-motion: reduce) {
  html { scroll-behavior: auto; }
}

BUG-004 🔴 Critical Mobile

Hero uses 100vh — clipped by mobile browser UI

What's wrong

The hero is sized with min-height:100vh. On iOS Safari and Android Chrome the dynamic address bar overlays the bottom of that box — the topic chips and scroll cue sit behind the browser chrome at 320–428px, and the layout jumps every time the bar shows/hides.

Location

.hero { min-height: 100vh } — hero section (#home)
Fix · CSS
.hero {
  min-height: 100vh;    /* fallback for older engines */
  min-height: 100svh;   /* stable: excludes mobile browser UI */
}

/* optional: grow into freed space when the address bar hides */
@supports (min-height: 100dvh) {
  .hero { min-height: 100dvh; }
}
BUG-005 🔴 Critical Interactions

Page keeps scrolling behind the open mobile menu

What's wrong

Opening the hamburger drawer leaves body scroll unlocked — users scroll "through" the overlay into the page behind, and the scroll position jumps when the menu closes (scrollbar removal isn't compensated). The drawer also lacks overscroll containment, so flings chain into the page.

Location

.mobile-nav drawer + burger button [aria-expanded] body scroll-lock logic (JS)
Fix · JS + CSS
const body = document.body;

function openMenu() {
  // compensate scrollbar width — zero layout shift on desktop
  const sw = window.innerWidth - document.documentElement.clientWidth;
  body.style.overflow = 'hidden';
  body.style.paddingRight = sw > 0 ? sw + 'px' : '';
  burger.setAttribute('aria-expanded', 'true');
}

function closeMenu() {
  body.style.overflow = '';
  body.style.paddingRight = '';
  burger.setAttribute('aria-expanded', 'false');
}

/* CSS — stop scroll-chaining out of the drawer */
.mobile-nav { overscroll-behavior: contain; }

BUG-007 🟡 Major Mobile

Long strings break out of cards on small screens

What's wrong

Unbreakable strings — inline code tokens, slash-separated paths, long compounds like «Промт-инжинирование» in the tokenization demo, footer URLs — push past card edges at 320px. Some get clipped by card overflow with no scrollbar: text is simply lost.

Location

inline <code>, .prompt-text tokenization example (#basics) footer links
Fix · CSS
code, .prompt-text, .card p, .footer a {
  overflow-wrap: break-word;   /* modern */
  word-break: break-word;      /* legacy alias — still needed on iOS 14 */
}

/* code blocks keep their formatting — they scroll instead (see BUG-001) */
pre, pre code {
  overflow-wrap: normal;
  word-break: normal;
}

BUG-009 🟡 Major Desktop

Keyboard focus states removed / invisible

What's wrong

A global outline:none (with no replacement) strips the focus ring from nav links, chips, copy buttons and the theme toggle. Keyboard users lose their position entirely — fails WCAG 2.4.7. Hover styling is not a substitute.

Location

global :focus styles .nav a, .chip, .copy-btn, .theme-toggle, .lang-switch

/* remove the default ring ONLY where a visible replacement exists */

:focus-visible {
  outline: 2px solid #1b5fd9;
  outline-offset: 2px;
  border-radius: 4px;
}

/* light-on-dark variant for the dark header / code panels */
.site-header :focus-visible,
.fix :focus-visible { outline-color: #8ab4ff; }
BUG-010 🟡 Major Interactions

All motion ignores prefers-reduced-motion

What's wrong

Scroll-reveal translate/opacity animations, smooth anchor scrolling and toast transitions run unconditionally. Users with the OS-level reduce-motion setting get no opt-out — a vestibular-safety issue, and an instant audit fail.

Location

.reveal transitions html { scroll-behavior: smooth } toast / chip animations
Fix · CSS
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
  /* never leave content hidden if the reveal animation is killed */
  .reveal { opacity: 1 !important; transform: none !important; }
}

BUG-012 🟡 Major Interactions

Hero topic switcher is not an accessible tablist

What's wrong

The «Текст / Изображения / Музыка / Видео» switcher is plain buttons toggling panels: no role=tablist/tab/tabpanel, no aria-selected, no roving tabindex, no Arrow-key navigation. Inactive panels stay in the tab order, so keyboard users tab through invisible content.

Location

hero switcher (#home) Текст / Изображения / Музыка / Видео + panels
Fix · HTML + JS
<div role="tablist" aria-label="Content types">
  <button role="tab" id="tab-text" aria-selected="true"
          aria-controls="panel-text">Текст</button>
  <button role="tab" id="tab-img" aria-selected="false" tabindex="-1"
          aria-controls="panel-img">Изображения</button>
  <!-- Музыка, Видео: same pattern -->
</div>
<section role="tabpanel" id="panel-text" aria-labelledby="tab-text">…</section>
<!-- inactive panels: use the hidden attribute, not just a class -->

/* JS — roving tabindex + arrow keys */
tabs.forEach(function (tab, i) {
  tab.addEventListener('keydown', function (e) {
    if (e.key !== 'ArrowRight' && e.key !== 'ArrowLeft') return;
    e.preventDefault();
    var d = e.key === 'ArrowRight' ? 1 : -1;
    var next = tabs[(i + d + tabs.length) % tabs.length];
    activate(next);
    next.focus();
  });
});
BUG-013 🟡 Major Interactions

«Скопировано» toast overlaps the header and stacks on itself

What's wrong

The copy-confirmation toast is fixed to the top-center — on mobile it lands directly under (or behind) the sticky header. Rapid clicks on multiple «Копировать» buttons spawn overlapping toasts with no stacking logic or live-region announcement.

Location

copy toast element position: fixed; top: 12px all .copy-btn handlers
Fix · CSS + JS
.toast-region {
  position: fixed;
  inset-inline: 0;
  bottom: calc(16px + env(safe-area-inset-bottom));
  display: flex;
  flex-direction: column;
  align-items: center;
  gap: 8px;
  pointer-events: none;
  z-index: 1000;
}

/* one reusable toast, retriggered — never overlapping copies */
function showToast(msg) {
  toast.textContent = msg;
  toast.classList.remove('show');
  void toast.offsetWidth;   /* restart the animation */
  toast.classList.add('show');
  clearTimeout(showToast.timer);
  showToast.timer = setTimeout(function () {
    toast.classList.remove('show');
  }, 2000);
}
/* give .toast-region role="status" aria-live="polite" */

BUG-015 🟢 Minor Cross-browser

backdrop-filter missing -webkit- prefix (Safari)

What's wrong

The translucent sticky header uses only the unprefixed backdrop-filter. Safari (through 18.x on many paths) requires -webkit-backdrop-filter — there the header renders fully transparent and nav text becomes unreadable over scrolled content.

Location

.site-header (sticky bar) any translucent overlay
Fix · CSS
.site-header {
  background: rgba(255, 255, 255, 0.85);  /* opaque fallback first */
  -webkit-backdrop-filter: blur(12px) saturate(1.4);
  backdrop-filter: blur(12px) saturate(1.4);
}
BUG-016 🟢 Minor Cross-browser

Scrollbar hiding only works in WebKit browsers

What's wrong

Horizontal chip rows hide scrollbars with ::-webkit-scrollbar only — Firefox still shows a chunky bar, breaking the intended look. Hiding the bar entirely also removes the scroll affordance; add edge fades instead.

Location

chip scrollers — video formula, prompting-methods row
Fix · CSS
.scroller {
  scrollbar-width: none;       /* Firefox */
  -ms-overflow-style: none;    /* legacy Edge */
}
.scroller::-webkit-scrollbar { display: none; }  /* Chrome / Safari */

/* keep a scroll hint via edge fades */
.scroller {
  -webkit-mask-image: linear-gradient(90deg, transparent 0, #000 16px,

  mask-image: linear-gradient(90deg, transparent 0, #000 16px,
              #000 calc(100% - 16px), transparent 100%);
}

BUG-018 🟢 Minor Performance

Font loading: no preconnect, no fallback stack (FOUC)

What's wrong

Webfont CSS loads render-blocking with no preconnect, and the body rule lacks a system fallback stack — first paint shows a mismatched fallback, then visibly reflows on swap (FOUC/CLS). Cyrillic coverage should be verified per family.

Location

<head> font <link> tags body { font-family } rule
Fix · HTML + CSS
<link rel="preconnect" href="https://cdn.jsdelivr.net" crossorigin>

/* CSS */
body {
  /* real fallback stack — no blank-text FOIT */
  font-family: "IBM Plex Sans", system-ui, "Segoe UI", sans-serif;
}
/* verify every @font-face ships font-display: swap
   (fontsource-generated CSS does by default) */
BUG-019 🟢 Minor Desktop

Card hover changes geometry → layout shift

What's wrong

On hover, cards add a thicker border / extra padding, nudging siblings by 1px on every mouse-over — visible jitter in dense card grids. Hover effects must be paint-only.

Location

.card:hover border/padding rules method cards (#basics), model cards (#music)
Fix · CSS
.card {
  border: 1px solid var(--line);
  transition: transform .2s ease, box-shadow .2s ease, border-color .2s ease;
}
.card:hover {
  transform: translateY(-2px);
  border-color: #1b5fd9;   /* color-only change — zero layout shift */
  box-shadow: 0 8px 24px rgba(16, 24, 40, 0.08);
}
/* need a thicker ring on hover? use an inset shadow, never border-width:
   box-shadow: inset 0 0 0 2px var(--accent); */
